## 进入修复里程碑的发现

### P1

1. **图纸收藏丢失研究关系。** 两张收藏只显示“轴测图表达参考 5-1 / 1-1”，没有原研究问题或“精细线稿 / 拼贴叙事”方向。API snapshot 已保存完整 `question`，属于 Board 投影缺口；V2 能找回图片，但不能完成核心 T7 的关系解释。
2. **空库默认工作区初始化竞态。** 每个全新隔离库第一次打开 Board 都在约 3ms 内创建两个同名“建筑研究工作区”，一个永久空置、另一个承载 Run。多个独立数据根重复，属于新安装初始化 P1。
3. **默认 no-key mock 的完成/展示合同脱节。** 默认 mock 资产没有 `text_excerpt`，workflow 可把 12 条资产计为 `completed / coverage_satisfied`，Board 却按证据展示合同隐藏所有案例。正文 analyzer 返回同 statement 的 excerpt 时，既有无 excerpt claim 也不会被升级。默认 mock 是项目声明的开发/测试/演示路径，因此按 P1 修复。

### 重复 P2（达到 2 个 persona）

1. **图纸计数口径不明（V1/V2）。** 顶部为 33/35 张，三个方向各 12 张、合计 36；页面没有解释顶部按图片去重、方向数字按关联计。
2. **图纸环境职责不明（V1/V2）。** “小红书可用 · 未启用页面高清图纸读取 / 连接 Chrome”同时出现，首见者不清楚小红书检索与 Chrome 页面读取各自负责什么。
3. **图纸选择按钮可访问名称重复（V1/V2）。** 每轮 36 个按钮都叫“选择此图用于收藏”，键盘/读屏用户无法辨认目标。
4. **任务书只显示数量、不显示文件名（B1/B2）。** 选择 PDF 后仅见“1 个文件待上传”，提交前无法核对是否选对任务书。

### 未达到阈值

- B2 收藏目录中两条不同原问题的可见文字清楚，但两个按钮的 accessible name 都只有相同子问题；仅在 B2 双记录场景观察到，记 P2 观察，不单独立项。
- 图纸收藏默认先打开“建筑方案”，即使当前只有图纸收藏；类型按钮的 0/1 或 0/2 计数仍能引导到正确标签，未造成任务失败。

## 应保护的行为

- 图纸入口会把问题占位符、CTA、七阶段状态和结果结构整体切到制图语域；提交后立即有状态反馈，约 3 秒到结果。
- 图纸按“方向 → 帖子 → 图片”组织，原笔记链接和权利状态在图片附近；批量保存明确提示“已保存 1 项，选择已清空”。
- 任务书入口对作用边界的解释清楚；提交按钮立即进入“正在准备研究…”，四个任务书专属问题直接证明 PDF 参与拆解。
- 建筑结果保留“代表案例 → 怎么做 → 适用条件 → 出处”；直接收藏原位变成“已加入收藏”。
- 建筑收藏目录以用户原问题为主标题、任务书衍生方向为副标题；同方向的 B1/B2 仍能凭原问题清楚区分。

## 模拟局限

- 本轮由同一执行 agent 顺序扮演四个 persona，不是四名独立真人；角色原话是按 persona 即时复述，不能代表真实情绪强度。
- agent 会完整读取 DOM，文案理解可能高估真人；可访问名称、计数、状态、API snapshot 与 Run coverage 是客观页面/数据证据。
- “一周后找回”仍是同会话即时模拟，没有真实遗忘。
- 图片、正文和 PDF 都是确定性隔离夹具，只验证交互、状态和证据投影，不代表案例研究质量。
- 任务书夹具曾经历四次不计分校准：未知域名未过可信来源门槛、同义句未过 formal evidence 精确绑定、mock 既有无 excerpt claim 阻止升级。最终 v5 才作为 B1/B2 有效场次。
