# M121 真实用户试点 · 观察工具包

目的：通过观察 2–3 名真实目标用户（建筑学生 / 青年设计师）完成自己的研究任务，验证产品的可理解性与核心任务完成度。这是 M121 保持 `in_progress` 的唯一关闭条件。

## 边界（不可违反）

- 参与者**自己发起**全部研究任务；观察者不代替操作，不预先创建 Run。
- 不截图参与者的个人内容；记录只使用下方的去身份化字段。
- 不引导措辞：可以说"请把你现在的设计问题输入进去"，不可以说"你可以输 XX 试试"。
- 观察者只在参与者明确卡住超过 2 分钟、或主动求助时介入，并先记录卡点再解释。
- 不承诺修改：现场不讨论"我们会怎么改"，只记录。
- "来源核验"不出现在任何任务、话术或记录字段中（该功能已删除）。

## 参与者画像

- 2–3 人；建筑学在校生（大二以上）或毕业 3 年内的设计从业者。
- 至少 1 人正在做真实课程设计/竞赛/毕设；至少 1 人此前从未见过本产品。
- 设备：使用我们准备的机器（服务已启动、干净浏览器标签），避免环境安装成为观察噪音。

## 任务清单（每人 60–90 分钟，按顺序）

| # | 任务 | 覆盖目标 | 完成标准 |
|---|---|---|---|
| T1 | 用自己的当前设计问题发起一次「建筑设计研究 · 概览」 | 首页可理解性、问题输入、三档语义 | 能不求助地发起并等到结果 |
| T2 | 阅读 T1 结果，用自己的话复述"这个研究告诉了我什么" | 结论/章节/案例结构可读性 | 复述包含 ≥1 条具体机制或做法 |
| T3 | 从 T1 结果中把 2 个有用案例加入个人收藏 | 选择条、保存反馈 | 独立完成保存并确认成功 |
| T4 | 关闭页面重新打开，找回刚才的研究 | 最近研究、记录标题、状态标签 | ≤1 分钟内找回 |
| T5 | 解释首页两条记录状态的区别（"研究已完成" vs "研究已形成初步依据"） | 状态语义、诚实降级 | 说出"后者不够完整/仅初步"之类的正确理解 |
| T6 | 上传一份任务书 PDF 再发起一次「标准」研究（可用我们准备的样例任务书） | 添加资料入口、任务书语义 | 理解任务书用于收束研究而非独立分析 |
| T7 | 发起一次「图纸灵感」（自己想出的图纸类型） | 视觉入口、方向组织 | 能说出方向之间的区别是"画法风格" |
| T8 | 从图纸灵感结果收藏 2 张图，并打开其中 1 张的原笔记 | 图片选择、来源入口 | 独立完成 |
| T9 | 打开个人收藏，找到 T3 保存的案例并解释"怎么做"部分 | 收藏目录、案例详情结构 | 找到并正确复述 ≥1 条做法 |
| T10 | （可选）删除一条收藏；解释"永久保留 / 还剩 N 天"的含义 | 删除、保留期语义 | 说出 14 天后自动删除的含义 |

## 每任务记录表（去身份化）

```
参与者编号: P1 / P2 / P3        任务: T_
背景: 学生-年级 / 从业-年限（不记姓名、学校、公司）
完成: 独立完成 / 提示后完成 / 未完成
用时: ___ 分钟（发起类任务只计操作时间，不计研究等待）
卡点: 在哪一步停下（引用界面上的文字，不解释原因）
原话: 参与者当时说的话（逐字，≤2 句）
误解: 参与者以为它是什么（如有）
求助内容: 参与者问了什么（如有）
```

## 会后 5 问（每人一次，开放式）

1. 哪个页面你看第一眼没看懂？
2. 有哪个词你不确定是什么意思？
3. 结果里你最想直接抄走的是什么？找到它花了多久？
4. 你会在什么时候再打开它？
5. 如果只能改一处，你改哪里？

## 分级与处置阈值

- **P0**（立即修）：数据丢失、无法发起研究、结果页空白/报错、收藏丢失。
- **P1**（本轮修）：核心任务（T1/T2/T3/T9）有人未完成或严重误解结果含义。
- **P2**（两人以上复现才修）：措辞误解、找不到入口但最终完成、期待落空。
- **P3**（记录不修）：审美偏好、单人特殊习惯。

单人单次的 P2 不触发实现，防止一条评论引发一次重设计；P0/P1 当天升级。

## 观察结论落点

- 每人一份任务记录表 + 会后 5 问，汇总到 `findings.md`（M121 小节），原始表存本地不入 Git。
- 2–3 人完成后 M121 才可标记 complete；结论同步 `task_plan.md` 与 `HANDOFF.md`。
- 修复排序进入常规红绿流程，先 P0/P1。
