# ArchResearch Web Edition 演示流程

对外演示以项目方私下提供的 Web Edition 地址为准：打开网页即可使用完整工作台，不需要 Python、Node.js、pnpm、PowerShell 或 API Key。下面第一条是维护者的离线 mock 回放，第二条才是普通试用者使用的网页流程。

## 演示前检查

维护者如需运行离线夹具，才使用 PowerShell 7：

```powershell
pwsh -NoProfile -File scripts/validate-evaluation-fixtures.ps1
pwsh -NoProfile -File scripts/start.ps1
```

这些命令只服务源码维护和离线回放，不是普通用户安装步骤。完成回放后运行：

```powershell
pwsh -NoProfile -File scripts/stop.ps1
```

### 网页版扩展安装

1. 按[Chrome 扩展安装说明](chrome-extension.md)加载独立扩展 ZIP。
2. 回到 Web Edition，从扩展工具栏点击“连接当前 ArchResearch 网页”，首次提示时允许网页读取。
3. 只有“小红书图纸灵感”会调用扩展；案例研究不需要扩展。研究进入终态后，扩展只关闭自己打开的研究标签页。

## 流程一：维护者离线 mock 回放（不属于公开安装）

**目标**：完整演示工作界面、证据分区、用户状态和导出，不调用外部网络供应商。

**前提**：保持默认 `ARCHRESEARCH_PROVIDER_MODE=mock`。不需要 OpenAI Key，也不需要给扩展全站权限。

1. 打开启动脚本输出的参考板地址。仅需要固定作品集画面时使用下面三个纯本地入口；`?demo=1` 继续兼容“形成方案依据”。要验证持久化闭环时使用正常地址。

   - 快速找方向：`http://127.0.0.1:5173/?demo=quick`
   - 形成方案依据：`http://127.0.0.1:5173/?demo=balanced`
   - 做跨案例论证：`http://127.0.0.1:5173/?demo=deep`

   三个入口不会创建 Workspace 或 ResearchRun，也不会请求任何外部供应商。仓库中的验收截图位于 `docs/assets/portfolio-demos/`。
2. 点“新建项目”，命名“旧厂房公共文化中心”。
3. 选择“建筑设计研究”，问题使用 `fixtures/queries/research_tasks.jsonl` 中的 `adaptive-reuse-boxes-01`，研究方式选“形成方案依据”；问题文本已经包含保留屋架和插入功能盒体的研究范围。
4. 提交后回到主页：研究是后台进程，从“最近研究”打开该记录查看当前阶段；完成后进入结果页。
5. 核对结果按“任务 → 研究结论 → 问题章节 → 完整案例答案”连续展开：每个案例只有项目名、机制、最多三条怎么做、一条适用条件、至多一张识别图和一个“出处 · 域名”链接，没有状态条、核对文案或折叠层。
6. 在案例选择条中勾选两个案例加入个人收藏。从主页进入收藏页，确认“问题目录 → 子问题详情”能读到刚保存的案例；刷新页面后收藏仍在。再保存一次同题新案例，确认旧收藏不被替换（保存是累加动作）。
7. 选 2–6 个案例打开“对照案例策略”，核对按解决对象、可借鉴方法、图中看到和适用条件逐项比较。
8. 至少两个不同项目时导出私有策略矩阵；再生成可分享结果板：未知或受限图片应降级为来源卡、署名和链接。

**完成判据**：无需 Key 即可得到非空案例答案；刷新后收藏仍在且旧收藏未被新批次替换；分享版没有完整嵌入未知/受限图片。

## 流程二：Web Edition 真实网页研究

**目标**：演示完整性优先的多轮网页搜索、浏览器候选图块识别、来源绑定和可恢复续研。

**费用与隐私提示**：这是主动启用的真实研究，由项目方配置 Provider 并承担模型费用。用户不填写 Key；长期记录保存在当前浏览器，浏览器登录态不会上传。

1. 打开项目方提供的 Web Edition 地址，选择“建筑设计研究”或“图纸灵感研究”。
2. 点“新建项目”，命名“中小型博物馆流线”，发起一个“做跨案例论证”的研究；也可先用“形成方案依据”控制研究范围。
3. 研究在后台进行，可随时回主页做别的事；只有小红书图纸灵感需要按扩展说明连接已登录的小红书 Chrome。
4. 结果出现后按问题章节阅读案例答案；每个案例的“出处 · 域名”链接可跳回源网页核对。
5. 用“对照案例策略”比较至少两个项目的流线做法，记录观众、工作人员、藏品运输的差异及适用条件。
6. 研究若因网页阻塞、限流或执行上限成为 `blocked`，确认已有证据仍被保留，再使用“继续补齐研究”；续研只查询仍为空白的子问题。只有逐题 coverage 与正文分析 enrichment 同时达到当前深度门槛，建筑先例研究才进入 `completed`。
7. 结束后检查研究标签页已关闭；需要收回全站权限时，在扩展中点击“撤销网页读取权限”。

**完成判据**：结果来自当次实时网页研究；至少一条正式事实能跳转到来源定位；失败页面不会清空已有资产；终态后研究标签页关闭，手动撤销能立即移除全站权限。

## 版本化真实评测记录

25 条任务的数据集本身不会联网。执行真实评测时应由操作者逐条主动启动，并另存下面的运行元数据：

- `evaluation_date` 与任务 `id`；
- 应用版本或 Git commit；
- provider、研究模型和视觉模型（不记录 Key）；
- 查询、访问页面数、运行时间与成本；
- 最终状态、`stop_reason` 和 CoverageReport；
- Top-5 图纸类型人工标注、重复项、来源归属是否正确；
- 因网页变化、验证码或访问规则造成的差异。

不要在 CI 或默认 `scripts/verify.ps1` 中批量执行 25 条真实任务。实时网页会变化且产生费用；作品集报告应明确执行日期和人工标注方法，不把离线合成分类集的成绩混同于真实网页召回率。
