# M121 目标用户试点 · 观察工具包

本工具包用于完成 M121 的最后一步：观察 2–3 名真实目标用户使用 ArchResearch。
代理问法轮（9 条去身份化问法 + 唯一 Quick `5e4184cf-...`）已完成，只能诊断问法形状与结果强度；
任务完成率、用时、导航、结果理解、收藏找回和恢复预期必须由真人操作得出。

## 1. 完成条件

满足以下全部条件后，M121 才能从 `in_progress` 改为 `complete`：

- 观察 2–3 名真实目标用户（建筑学生或青年设计师），每人一场独立会话，编号 U1/U2/U3。
- 全部实际场次（2–3 场）合计，每个任务（T1–T9）至少被执行 2 次；仅 2 场时，带 ◇ 的任务不可跳过。
  T4 的执行以"发起成功"为计数口径，不要求读取结果。
- 全部观察以去身份化编号记录进第 5 节的记录表；原始记录表归档到 `docs/m121-records.md`。
- 发现按第 6 节分级；只有 P0/P1 与重复 P2 进入 `findings.md` 立项，处置决定写入 `task_plan.md`。
- 全部计划场次完成且第 6 节处置闭环后，M121 标记 `complete`。

## 2. 参与者、场次与会前预检

- 人数：2–3 人；目标画像：正在做课程设计、竞赛或毕业设计的建筑学生，或工作 0–3 年的青年设计师。
- 时长：每场 **60 分钟**（5 分钟开场 + 约 45 分钟任务 + 10 分钟结束访谈）。等待时间已按下表计入编排：
  概览档 Run 约 3–8 分钟；标准档（任务书）Run 约 10–20 分钟，因此 T4 只发起、不等待结果。
- 参与者用自己的真实设计问题；没有合适问题时，才提供主页四个起始问题作为兜底。

会前预检清单（全部只读或只启动服务，不创建、不 retry、不删除任何 Run）：

1. `scripts/start.ps1` 确认 API 8000 / Board 5173 健康。
2. 涉及 T5 时，`opencli doctor` 确认 XHS 搜索面可用。
3. 打开 Board 确认最近研究列表同时可见"研究已完成"与"研究已形成初步依据"两种状态，
   且至少一条记录显示保留倒计时或"永久保留"；缺任一状态时，T9 改用可展示的既有记录并提前标记。
4. 确认最近研究列表条目多于滚动窗口可视区（约 3 条），否则 T8 的"滚动窗口是否被发现"记"不适用"。
5. 准备 1 份去身份化任务书 PDF（会前打开确认可读），供 T4 使用。
6. 指定一条已完成的历史记录作为**兜底阅读记录**：当 T2 的实时 Run 失败或超过 10 分钟未完成时，
   T3/T6/T7 切换到兜底记录执行，并在记录表标注"兜底路径"。

## 3. 主持边界（不可越过）

- 参与者自己操作、自己发起研究；主持人不代点"开始研究"。
- 研究档位由参与者自选，主持人不预先建议；参与者自选并说出理由后（T2 观察点），
  若选择了标准或深入档，主持人可以时间为由请其改用概览，该干预按提示规则记录在案。
  T4 固定使用标准档是任务脚本参数，不适用此条。
- 出声思考法：请参与者边操作边说出预期与困惑；参与者卡住满 60 秒（主持人计时）后才允许提示；
  每次提示记录触发时刻与内容。
- 不引导术语：主持人不先说出"案例""机制""收藏"等产品词；参与者自己说出某词后方可复用。
  任务脚本已使用中性措辞，照稿念不会泄词。
- 全程不截图、不录屏；记录只写去身份化文字。
- 封存 Run（`10d31b4c-...` 等）不 retry、不删除、不改保留状态；T9 为口头问答，参与者不做点击操作。
- 参与者创建的 Run 属正常产品使用，遵守单活跃 Run 门；等待期不得发起第二个 Run；会后不删除。
- 不恢复 Firecrawl。本试点考察结果状态理解（T9），不考察来源核验；参与者若自发表达对结果出处
  或可信度的疑问，记录原话，不引导、不解释、不追问。

## 4. 任务脚本与场次编排

核心任务：**T2、T3、T6、T7**（失败按 P1 起评）；T1/T5/T8/T9 失败默认 P2 起评，
除非伴随数据丢失或信任破坏。◇ = 时间不足时可跳过（受第 1 节合计 ≥2 次约束）。

执行顺序与等待期编排（约 45 分钟任务净时长）：

```
T1 → T2 发起 → [T2 等待期：T9 口头问答] → T3 → T6a（建筑侧保存）
   → T5 发起 → [T5 等待期：T8 ◇] → T5 结果 → T6b（图纸侧保存）
   → T7 → T4 ◇（只发起）→ 结束访谈（T4 Run 在后台运行，不等待）
```

### T1 · 首次理解（≤5 分钟）
- 说：请看这个页面，先不点击。（最多看 2 分钟）你觉得这个工具是做什么的？你会用它做什么？
- 观察：能否区分"建筑设计研究 / 图纸灵感"两个入口；对三档研究方式的第一反应（勾选项）。
- 判据：用自己的话说出"找案例回答设计问题"或"找图纸风格参考"之一。
  算通过："帮我找参考案例""找别人怎么解决这种问题""找出图风格"；
  不算通过：只说"搜建筑资料""像百度一样搜索"而说不出问题导向。

### T2 · 发起一次建筑研究（核心；计时止于点击"开始研究"）
- 说：用你现在课程设计里真实卡住的一个问题，发起一次研究。档位你自己选，选的时候说说为什么。
- 观察：输入过程整句删除重写次数；是否询问"该怎么问"；从开始输入到提交是否超过 60 秒；
  是否注意到"添加任务书或案例页（可选）"（勾选项）；自选档位与理由。
- 判据：不经提示完成发起；能说出所选档位的取舍近似含义。
  参考口径：概览 = 更快、方向性；标准 = 更全面、形成依据；深入 = 跨案例论证、更久。
  说出"深度/覆盖与时长的取舍"任意近似表述即通过。
- 发起后进入等待期（单独记"Run 等待时长"），立即执行 T9。

### T9 · 状态与保留期理解（口头问答，参与者不点击；在 T2 等待期执行）
- 说：（指向预检确认过的两条既有记录）这两条，一条写"研究已完成"，一条写"研究已形成初步依据"，
  你觉得区别是什么？（指向带倒计时的记录）这条写"还剩 N 天"，你觉得会发生什么？你会怎么处理？
- 观察：对"初步依据"的解释；悬停提示是否被发现（勾选项）；对到期删除的理解与焦虑表现（以原话为准）。
- 判据：说出"初步依据 = 覆盖了问题但案例数量或深度不足"的近似含义；
  说出"到期会删除、设为永久可以阻止"的近似含义。

### T3 · 阅读结果并复述（核心；T2 结果渲染后另起计时）
- 说：研究完成了。请读这个页面，然后合上说给我听：它告诉了你什么？你下一步会做什么？
- 观察：阅读顺序（先结论还是直接跳案例，勾选项）；"怎么做 / 适用条件"是否被理解为
  可执行步骤与前提；图纸类型筛选器是否被发现（勾选项）；对结果出处/可信度的自发疑问只记原话。
- 判据：复述内容能与任一案例"怎么做"一节的任一条对应（对应不上时记录原话，会后两人复核）；
  能说出适用条件是"什么情况下能用"。
- T2 Run 失败或超 10 分钟：按第 2 节切换兜底记录，记录表标注"兜底路径"，结果档记"系统原因中断"。

### T6a · 保存建筑结果（核心；T3 之后立即执行）
- 说：把这次结果里你真正想留下的内容保存起来，方便下周再用。请操作给我看。
- 观察：勾选语义是否清楚；底部条"已选 N 项"是否被理解（勾选项）。
- 固定追问：刚才保存成功了吗？你怎么知道？（回答引用了成功反馈即算"注意到反馈"）
- 判据：完成保存；能说出保存后去哪里找（参考答案：主页"个人收藏"或等价路径描述）。

### T5 · 图纸灵感（发起后等待期执行 T8）
- 说：假设你要出一张轴测图（或你正要画的图），想找不同的表达风格。请发起一次图纸灵感研究。
- 观察：输入重写次数与求助次数（同 T2 口径）；结果渲染后对"方向 → 帖子 → 图片"结构的理解；
  对权利说明的反应（以原话为准）。
- 判据：完成发起；结果渲染后能指出一个自己愿意参考的方向。
- 会中 XHS 失效：结果档记"系统原因中断"，跳过判据后半，不重试。

### T8 ◇ · 历史重开（在 T5 等待期执行）
- 说：请找回你今天做的第一次研究，重新打开它。
- 观察：最近研究列表的扫描方式；标题是否可辨认；滚动窗口是否被发现
  （仅当列表长于可视区时评估，否则记"不适用"）。
- 判据：不经提示打开正确记录。

### T6b · 保存图纸结果（T5 结果渲染后）
- 说：这次的结果里有你想留下的吗？有的话同样保存起来。
- 观察与判据同 T6a；两侧都保存过才能支撑 T7 的类型切换观察。

### T7 · 找回保存的内容（核心）
- 说：现在假设过了一周，你要把今天留下的东西找出来用。请找到它们（建筑和图纸的都要）。
- 观察：从主页找到入口的路径；目录 → 详情的导航；是否切换到正确类型标签找到两类内容（勾选项）。
- 判据：不经提示找到两类已保存内容；能说出目录条目与原研究的关系
  （参考要点：条目按研究问题组织 / 点开即看到该次研究保存的案例或图纸；说中任一即通过）。

### T4 ◇ · 任务书路径（只发起，不等结果；放在结束访谈前）
- 说：这是一份项目任务书 PDF。请用它发起一次标准档研究。
- 主持人须知：本任务只考察入口寻找与预期表达，到"发起成功并说出任务书作用"即止；
  Run 在结束访谈期间后台运行，不等待、不阅读结果。若访谈结束时已完成，可追加一问
  "和你预期的一致吗"，否则跳过。
- 观察：能否找到"添加任务书或案例页（可选）"入口；对任务书作用的预期。
- 判据：完成上传并发起；能说出任务书的作用（约束/聚焦研究问题的近似表述）。

## 5. 记录表

每任务一行，去身份化填写：

| 字段 | 说明 |
|---|---|
| 参与者 | U1 / U2 / U3 |
| 任务 | T1–T9（T6 分 a/b） |
| 起止时间 | 按第 4 节各任务计时锚点；含 Run 的任务另记"Run 等待时长" |
| 结果 | 独立完成 / 提示后完成 / 未完成 / 系统原因中断（注明服务与现象） |
| 提示 | 次数 + 每次触发时刻（相对任务开始）+ 提示内容一句话 |
| 走错路 | 次数 + 每次走到了哪里 |
| 观察点勾选 | 该任务预置勾选项，记 发现 / 未发现 / 不适用；"被发现"= 点击、悬停停留阅读、或口头提及之一 |
| 原话摘录 | 疑惑、误解、称呼方式（不写身份信息）；情绪与反应类观察以原话为准，无原话记"无可观察证据" |
| 理解核对 | 该任务判据的回答概要 |
| 候选缺陷 | 描述 + 初步分级（P0/P1/P2） |

## 6. 缺陷分级与处置

- **P0**：数据丢失、核心流程走不通、明显破坏信任（如结果与操作不符）。→ 立即停止排期新任务，当轮修复。
- **P1**：核心任务（T2/T3/T6/T7）失败或结果含义被系统性误解（如把初步依据当作失败、找不到已保存内容）。
  → 试点结束后立即修复。
- **P2**：措辞、摩擦、偏好类问题。→ 同一模式在 ≥2 名参与者身上重复才立项；单人意见记录但不立项。
- **系统原因中断**不计入完成率，不直接触发 P0/P1，记为环境事件单独跟进。
- 单条评论不触发重设计；所有立项修复走既有红绿与完整门禁流程。

## 7. 结束访谈（10 分钟；T4 Run 后台运行中）

1. 用一句话向同学介绍这个工具，你会怎么说？
2. 今天哪一步最顺？哪一步最想放弃？
3. 结果页里你最信任的是哪部分？最不信任的是哪部分？为什么？
4. 如果下周交图，你会再打开它吗？打开后第一件事做什么？
5. （若 T9 出现焦虑）你希望研究记录默认保留多久？

## 8. 产出与归档

- 每场结束当天：原始记录表誊入 `docs/m121-records.md`（去身份化）；
  按第 6 节分级后，只把 P0/P1 与重复 P2 写入 `findings.md`（单人 P2 若需引用，标注"记录不立项"）。
- 处置决定写入 `task_plan.md`。全部计划场次完成且处置闭环后，M121 标记 `complete`；
  后续修复各自立项，不并入 M121。
- 本工具包本身不创建 Run、不截图、不改动 durable 数据。
