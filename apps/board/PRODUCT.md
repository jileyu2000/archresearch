# Product

## Register

product

## Users

建筑学生和青年设计师，在课程设计、竞赛、毕业设计与前期方案推敲中，需要从网页里快速找到能够回答具体空间或出图问题的平面、剖面、分析图与效果图。

## Product Purpose

建筑设计研究把方案问题拆成可研究的子问题，并把多轮网页研究收束成可直接阅读的案例答案；图纸灵感接受“我想出一张轴测图，帮我找风格”“效果图怎么出”这类宽泛提问，围绕用户指定的图纸类型扩展不同表达风格，再组织成视觉灵感板。成功不是给出一段聊天答案，而是让用户直接看懂落地案例如何回答方案问题、不同视觉方向各自提供了什么制图启发，并能够筛选、收藏和按权利边界导出参考资产；案例策略另可按需对照。

## Editions And Data

- 本地安装版继续面向 Windows/Chrome：用户自行配置 Provider Key，API、SQLite、文件、历史研究与收藏都在本机运行和保存。
- Cloudflare Web Edition 是独立部署目标：拿到链接即可开始实时公开网页研究，不要求用户配置 Key，模型费用由项目方承担。项目方 Key 只存在 Cloudflare Secret，不能进入浏览器 bundle、存储、响应或 Trace。
- Web Edition 的建筑案例研究无需扩展；图纸灵感通过 ArchResearch Chrome 扩展读取用户已登录的小红书公开笔记。主页面在未检测到扩展时提醒安装与连接，检测成功后不再弹出；Cookie、账号、密码和浏览器存储不得上传到 Cloudflare。
- Web Edition 的长期 workspace、Run、结果、收藏和历史默认只保存在当前浏览器的 IndexedDB；PDF、图片等较大文件优先保存在 OPFS。用户可导出和导入版本化备份。清除站点数据、使用无痕模式、换浏览器或换设备都可能失去未导出的记录。
- 云端只允许保存运行中的最小 checkpoint、费用预留和临时素材，必须设置 TTL 并在交付或终止后删除；不建立平台案例库、跨用户历史或永久云端研究档案。
- Web Edition 的匿名研究入口先通过 Turnstile、设备/网络配额、单次页面/查询/时间/Token 预算和全局费用熔断，再允许进入 Provider。停用开关或预算不足时必须在产生模型费用前拒绝。
- GitHub 只作为本地安装版和项目资源展示页，不公开 Web Edition 地址；网页链接由项目方单独提供给指定试用者。

## Brand Personality

清醒、轻快、可靠，像一张正在工作的建筑图桌。任务入口可以有活力和一点工作室幽默；结果、来源和权利判断保持严谨。语气直接、具体，不用营销话术。

## Anti-references

- 不做聊天优先界面。
- 不做圆角堆叠、渐变与大指标组成的通用 SaaS 仪表盘。
- 不做相同图纸卡片铺满页面的结果墙，也不在项目档案内继续嵌套卡片。
- 不把来源可信度、图片归属和版权状态混成一个模糊分数。

## Design Principles

- 主页先呈现具体问题、研究入口和最近任务；进入研究任务后，研究结构与图纸先于控制器。
- 最近研究直接平铺全部项目中的 Run，不显示“当前项目 / 历史归档”、项目选择器、独立归档区、完整历史弹层或重复的“查看上次结果”。完整记录列表放在最大 320px / 45dvh 的具名原生滚动窗口中，默认只露出约三条但保持全部记录和保留动作可键盘访问，不把主页随历史数量持续拉长；标题说明与“新建项目”保持同一紧凑头部。每条记录名只从该 Run 的完整研究问题确定性概括，去掉口语开头并限制为 28 个字符：多个连续问句优先采用最后一个完整问句，单个长问句保留首个场景分句并让待解决动作进入标题；列表最多显示两行。完整问题仍保存在 Run 和结果页。现有与未来 Run 使用同一规则，不调用模型，也不把项目名当作记录名。打开记录时只在后台切换其所属项目；“新建项目”保留为唯一显式项目动作。新建历史 Run 从创建日起保留一学期（180 天），用户可单独设为永久保留，取消永久后从操作日起重新获得 180 天；既有记录沿用已存到期日，历史管理不承担跨 Run 记忆提炼。
- 建筑设计结果按“任务 → 研究结论 → 问题章节 → 完整案例答案 → 继续使用工具”展开，不重复显示问题拆解，也不显示完成状态条、研究进度、核验状态或证据入口；每个案例保留一个安静的出处链接；未结束或失败的 Run 仍保留必要状态与恢复动作。图纸灵感结果按“任务 → 灵感方向 → 制图灵感 → 继续使用工具”展开。建筑设计提供案例策略对照、跨案例策略矩阵与分享结果板；图纸灵感提供表达规范、个人收藏入口与来源板，不提供独立对照。两种结果的选择条都能把明确选中的参考加入个人收藏。
- 个人收藏是用户主动策展的长期资料，不是导出文件或自动记忆。主页入口进入完整收藏页，不使用弹窗；打开后默认建筑方案，顶部常驻建筑方案 / 图纸灵感两个同级切换，下方只呈现当前类型。建筑方案先显示平铺的“问题目录”，每一行以用户原研究问题作为主标题、以系统拆出的“研究方向”作为副标题，并显示已收藏案例数；点入后不再重复原研究题目，只以当前研究方向为标题展示案例答案，并通过“返回问题目录”回到目录。每个案例依次显示去除 ArchDaily 等发布媒体后缀的项目名、核心解法、最多三条可执行步骤、一条去除原文/来源审计语句后的适用条件和最多三张识别图片；建筑收藏保留删除动作和每案例一个出处链接，不显示其他来源入口。项目条件、完整边界、逐字证据与来源仍保存在收藏快照，不在收藏页重复铺开，也不借用另一子问题的机制。宽屏以解法 / 识别图 `1.05fr / 0.95fr` 两列组织，≤1180px 恢复单列，首图始终占满图片列、后两图并排。图纸灵感收藏保持图片、高清入口、来源和删除行为，并在每张图下显示原研究问题与灵感方向；旧收藏从关联 Run 回填，无法恢复时诚实标为历史未记录。切换收藏类型、返回主页或重新打开收藏都会回到建筑目录。结果页每个案例直接提供“加入个人收藏”，成功后原按钮就地变为“已加入收藏”；同时保留“选择案例”用于多选与对照，批量保存后明确显示“已保存 N 项，选择已清空”。建筑案例按“子问题 + 代表资产”独立选择，同一资产被多个子问题调用时不会联动。保存请求按资产合并但只写入明确选中的子问题；保存是累加动作，新批次不删除任何既有收藏（包括同题旧批），删除永远只由用户逐项执行。普通 Run 过期不会删除收藏快照、逐题研究包、案例图片索引和独立本地图，用户仍可单独删除收藏。
- 任务启动器只有两个同级主入口：“建筑设计研究”负责项目案例和设计策略，“图纸灵感”负责配色、线型、版式与分析图。
- 建筑设计的“研究方式”在主问题下方常显为紧凑三选一，并只提供可选“项目任务书（PDF）”与“指定案例或项目网页”。任务书只收束同一条研究：主动作始终是“开始研究”，系统在后台先以不创建 Run、不保存 artifact 的请求读取项目对象、场地、功能、限制、研究任务与成果要求，生成与当前档位一致的 3/4/6 个 typed subquestions，再上传任务书并创建普通 Run；后续 planner 直接使用这组问题。Board 不显示单独的任务书分析、边界预览或问题确认界面；选中文件后在主动作旁平铺显示完整文件名，允许提交前核对。后台读取失败时保留原文件与问题并显示简短错误，不静默绕过任务书约束；没有 PDF 时继续使用原来的直接开始路径。URL 只作为独立研究线索且不承诺优先访问。图纸灵感不显示这组资料，自动使用小红书；研究环境也只在图纸灵感中常显，并用“小红书负责查找、Chrome 负责当前页面高清图”的短句区分两种能力。切换场景会清空上一场景尚未提交的 URL/文件，防止隐藏资料误提交。
- 三种研究方式只显示“快速找方向 / 形成方案依据 / 做跨案例论证”，都以多个具体项目案例为依据，不以反复死磕某个网页来区分深度；内部 `quick/balanced/deep` 请求值不变。
- 图纸灵感不显示研究方式。界面提交固定兼容模式，后端统一使用 48 个逐图检查槽位 / 48 MiB 的固定预算；最近研究只标记“图纸灵感”，不展示虚假的深度差异。
- 结果顶部先给一条可直接理解的设计判断和至多三条立即动作。简短的正常综合原样保留；本地 fallback、带系统前缀或异常超长的综合只从既有证据链机制与转译中做展示投影，不生成新事实。建筑结果的动作去除“转译建议”等包装和来源审计尾句，适用条件取第一条非审计边界，不显示折叠审计层；图纸灵感继续沿用既有完整综合交互。
- 来源价值按任务意图区分：项目官网与 ArchDaily、Designboom、Dezeen、Divisare 等可信建筑媒体支持落地案例、空间机制和设计策略；同轮不同问题轮换站点，只有正文证据完整且在可比较尺度上直接回答当前子问题的项目进入正式结果。房间、家具或临时装置只能类比建筑尺度决策时不算正式案例。快速模式也至少需要三个正式项目，不能由两个项目反复覆盖三个研究问题。小红书只支持配色、线型、版式、形体推演和分析图语言。两类结果不得放进同一种项目卡或按单一可信度轴排序。
- 图纸灵感先把宽泛需求规划为互不重复的短风格方向。用户点名一种图纸时，所有方向固定该类型、只变化表达语言；只有未指定类型时才选择合适图纸类型。说明只列线宽、配色、纹理、构图、光影或注释等可见检索特征，不拆功能、流线、项目条件或来源核验问题。
- 图纸灵感对每个方向只执行一次排序搜索，按 rank 最多尝试四篇笔记并累计三篇有可用视觉资产的帖子；每帖仍最多四图。小红书已有候选时不再并行混入同题通用网页来源；OpenCLI 搜索失败或为空时才使用既有扩展后备路径，两条小红书路径都不可用时诚实终止、不得降级为通用网页素材；所有路径始终服从 48 个逐图检查槽位 / 48 MiB 总预算，容量耗尽时用产品文案明确说明，不误称时间超限。
- 视觉平台结果按“灵感方向 → 帖子 → 帖子内图片”进入独立灵感板。帖子统一承载标题、整体观察、来源与权利说明；图片保留逐图类型、过滤、溯源和独立选择。顶层图片总数按不重复资产计算，并明确同一张图可关联多个方向；各选择按钮的可访问名称必须包含方向、帖子、图纸类型与序号。视觉帖子与图片都不计入方案项目数量，也不能单独形成正式项目事实、图片归属或权利结论。
- 后台项目研究包继续聚合同一项目的正文来源、逐字引文、分析和图片索引，不同项目不得合并。建筑结果页不投影这些研究过程字段：每个有可用结果的子问题只显示一次题目级结论，随后按既有项目顺序把全部合格案例各显示一次；每项只保留去除发布媒体后缀的项目名、逐题空间机制、去重后最多三条可执行做法、第一条非审计适用条件、一个出处链接和最多一张可用识别图。没有图片时直接保留文字答案，不显示来源占位或重试；无可用结果的分支显示诚实短提示，待归组线索不进入答案页。同一项目对应不同子问题时仍分别读取自己的分析，不复用泛化结论。
- `verified/partial/visual_lead`、relevance、权利和来源字段继续用于后台排序、持久化与导出边界；建筑结果与建筑收藏不显示这些状态或分数。图纸灵感继续沿用自己的帖子来源与权利表达。
- 建筑案例答案使用连续文档流和结构线，不使用台账列、嵌套卡片或折叠层。宽屏文字与单张识别图组成两列，≤860px 恢复单列；图片保持原比例，只标图纸类型。建筑结果页不提供图纸类型筛选器；390px 下案例选择动作的命中高度不小于 44px。
- 整个视口是建筑工作面：宽屏余量由统一的制图网格和任务相关线稿组织，不把产品缩成居中的应用卡片。
- 证据贴着资产出现：来源支持的事实、图像中直接可见的观察、设计方法推断和适用边界永不混写。
- 建筑结果与建筑收藏的每个案例保留一个安静的出处链接（“出处 · 域名”，点击进入源网页），但没有来源检视器入口、核验状态文案、收藏/拒绝来源动作或研究备注。来源数据仍留在 durable snapshot 与导出边界；图纸灵感既有来源交互不在本次改动范围内。
- 建筑设计的对照必须产生判断：按解决对象、可借鉴方法、图中看到和适用条件逐项比较，不显示来源或证据状态，也不把卡片简单并排。对照入口和对话框统一叫“对照案例策略”。图纸灵感不提供对照工作流，逐图选择只用于导出。
- 研究过程只用于内部诊断：结果页不提供 Trace 入口或过程抽屉；运行中的用户状态只呈现当前阶段与必要的失败说明。
- 后处理工具不得抢在结果之前：案例策略/案例导出只在建筑研究结果之后出现，图纸表达/表达规范/灵感导出只在图纸灵感结果之后出现；未满足选择条件时保留具体的禁用说明。
- 备份与恢复页使用成熟产品常见的短动作词：页首只说明数据保存在本机，并提醒定期下载、需要时恢复。备份区只保留“当前数据 / 最近备份”两行状态、包含与排除范围一句话和“下载备份”主动作；超过 14 天仍以文字加警示色提醒，且明确记录仅属于当前浏览器。恢复区在桌面用后果说明 / 文件任务双列，窄屏恢复单列；先说明“替换当前全部数据，不会合并”，选中文件后自动检查且不改动数据。检查通过后展示备份与当前数据计数对照；危险动作命名为“替换当前数据并恢复”，要求一次内联最终确认（取消在前）。失败先说明当前数据未受影响或已退回原状；页面不出现打包或校验等内部术语。
- 高密度但不含糊：用清晰层级与固定词汇承载专业信息。
- 权利门禁可预期：私有导出与分享导出的差异在动作前说明。
- 两类导出产物不能共用泛化模板：建筑设计板把项目条件、设计机制、转译、边界和逐字证据贴在案例旁；图纸灵感板以帖子为单位承载标题、整体观察、来源与权利，图片只显示图纸类型，并把已保存的表达规范一起带出。

## Accessibility & Inclusion

以 WCAG 2.2 AA 为目标，支持键盘操作、可见焦点、非颜色状态提示、中文可读字号和系统减少动态效果偏好。桌面为主要工作面，窄屏仍保留完整任务能力。
